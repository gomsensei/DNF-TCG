# DNF TCG 웹 개발 계획

`web/`에 첫 관전형 프로토타입을 구현했다. 현재 기능·검증·제한 사항은 `IMPLEMENTATION.md`, 실행은 루트 `README.md`를 확인한다. 아래 순서는 최초 개발 계획이며 완료 상태를 의미하지 않는다.

## 목표
브라우저에서 봇끼리 대전하는 과정을 구경하며 규칙과 전략을 확인하고 반복 실험으로 밸런스를 분석한다. 직접 플레이가 주 목적은 아니다. 양쪽 손패를 동시에 공개하는 관전 화면을 기본으로 하며 봇은 상대 손패를 보지 못한다. Codex Sites 배포를 목표로 하며 초기에는 브라우저 내부 상태와 로컬 저장만으로 동작하도록 설계한다.

## 작업 순서
1. 카드 데이터와 엔진: 리더 3종, 동료 14종, 기본 포함 스킬 23종, 이벤트 10종, 몬스터 11종. 몬스터는 공용 50장, 플레이덱은 50장·동일 카드 최대 4장. 기본 스킬 2종은 덱 밖이다. 리더별 합법적인 테스트 덱을 구성하고 카드 ID와 명시 효과를 대조한다.
2. 상태 전이와 검증: 준비·멀리건·6단계 턴, 이동·사냥·결투 하위 단계·지불·운영·레벨업·승패를 구현한다. 순수 엔진으로 한 판을 끝내고 같은 시드와 행동으로 재현한다.
3. 기본 봇과 관전 화면: 합법 행동만 선택하는 봇을 먼저 연결한다. A/B 양쪽 손패·전장을 동시에 보여주고 자동 진행·일시정지·한 행동 진행·속도 조절과 현재 단계 안내를 제공한다. 선택 카드 상세·전투 계산·행동 로그를 연결한다. 수동 조작은 개발 검증용으로만 둔다.
4. 전략과 반복 실험: 사냥·성장·공격 정책을 추가한다. 파티 조합은 휴리스틱으로 후보를 줄이며, 실제 실행 전 엔진에서 검증한다. 한 판 관전 모드는 행동마다 멈출 수 있게 하고 대량 실행은 연출을 생략한다. Web Worker 실행·진행률·취소·결과 내보내기를 제공한다. 시드·행동 로그로 다시 보기를 구현하며 임의 시점 이동은 스냅샷 또는 재실행으로 복원한다.
5. Sites 배포: 현재 설치된 Sites 스킬로 새 프로젝트를 준비하고 build/test/typecheck, 자산 경로, 새로고침, 저장, 워커 동작을 확인한 후 기본 비공개 사이트로 배포한다.

## 제안 구조
```text
AGENTS.md
docs/DEVELOPMENT.md
docs/RULE_DECISIONS.md
docs/UI_DIRECTION.md
web/                       # 구현 단계에서 생성
  src/engine/              # 상태, 행동, 합법성, 판정, 효과, 관측, 시드
  src/data/                # 카드, 테스트 덱, 규칙 버전
  src/bots/                # 정책과 평가
  src/components/          # 전장, 카드, 상세, 로그, 덱 편집
  src/workers/             # 배치 대전
  tests/                   # 판정 시나리오, 불변식, 리플레이
  public/assets/           # 이미지와 source-manifest.json
```
호스팅 starter에 맞춰 라우팅·설정 위치를 조정할 수 있다. 엔진과 데이터는 라우팅 프레임워크에서 독립시킨다. 기존 WindSlayer의 Sites/Vinext 구조는 참고 근거이며 버전·설정 복사본이 아니다.

## 필수 검증
- 사냥·결투의 초과·동률·미달, 파티 손실과 리더 대체 손실.
- 파밍 카드 상태, 비용과 레벨업 중복 사용 방지, 카드 총수·인스턴스 유일성.
- R01~R10과 EV7·EV8·EV9, S20 비용 지불 전 조건, 케이트 Lv2 탐색 우선순위.
- 드로우 실패·5히트·히트용 덱 부족·몬스터덱 소진과 턴 종료 순서.
- 관전자는 양쪽 손패를 조회할 수 있지만 봇 관측 정보에는 상대 손패·덱 순서·비공개 히트가 없는지 확인한다. 일시정지 중 상태 고정, 한 행동 진행의 단일 처리, 속도와 무관한 같은 결과, 리플레이 재현, 저장 버전 불일치 처리를 검증한다.
- UI는 1440px·1024px·390px 기준. 좁은 화면은 던전·전장·상세를 전환하고 필수 행동을 호버에 의존시키지 않는다.

## 실험 결과
리더·덱·봇·규칙 버전, 시드, 선후공, 게임 길이, 종료 원인, 레벨 도달 시점, 파밍 수입·지출을 기록한다. 선후공을 바꾼 짝 대전과 복수 전략 봇을 사용하고 승률의 표본 수와 신뢰구간을 표시한다. 봇 대전 결과를 사람 대전 밸런스로 단정하지 않는다.
